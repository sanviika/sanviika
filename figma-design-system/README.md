# Northstar — Atomic B2B Design System for Figma

A Figma plugin that generates a complete, documented **atomic design system** for B2B SaaS directly inside your Figma file. It includes variables, styles, components, variants, Light & Dark modes, Comfortable & Compact density, and one documented page per element. It can also import the organisms in your existing product file and bind them to the new tokens.

> Why a plugin? Figma's REST API is read-only for design content. Pages, variables, styles and components can only be created by a plugin running inside the file. Running this plugin once in your file builds everything below.

---

## Run it in your file (2 minutes)

1. Open the target file in the **Figma desktop app**:
   `https://www.figma.com/file/rsapZ9I0d4nHSKEb9ZwEhN?node-id=6349:84202`
2. **Plugins → Development → Import plugin from manifest…** and pick `figma-design-system/manifest.json` from this repo.
3. **Plugins → Development → Northstar B2B Design System Generator**.
4. Keep the defaults:
   - **Source node** `6349:84202`. The plugin reads this node's colours and font, generates the brand ramp from its dominant brand colour, and imports each top-level frame as an organism component bound to the tokens.
   - **Brand colour override**: optional. Leave it empty to use the source colour.
   - **Build page templates**: on.
5. Click **Generate design system**. It takes 1–3 minutes, and the log shows progress and a summary.

Re-run with **Rebuild** ticked to delete the previous build (pages, variables, styles) and regenerate it.

> **Dark mode needs a Figma Professional plan or higher.** Free (Starter) files allow only one variable mode per collection. On a Starter plan the plugin still builds everything in Light, then tells you that dark mode was skipped.

## What gets generated

### Variables (4 collections, ~210 variables)
| Collection | Modes | Contents |
|---|---|---|
| **Primitives** | Value | Neutral, brand (generated from your file), green, amber, red, blue, teal, violet ramps. Hidden from pickers (`scopes: []`). |
| **Color** | **Light · Dark** | 70+ semantic tokens: `bg/*`, `text/*`, `border/*`, `icon/*`, `shadow/*`, `focus/*`, `chart/1–6`. Each is aliased to primitives, scoped, described, and has `var(--ns-*)` code syntax for Dev Mode. |
| **Dimensions** | **Comfortable · Compact** | `space/0–2000` (4px grid), `radius/*`, `border-width/*`, `size/control-*`, `size/table-row`, `size/nav-height`, `size/sidebar`… |
| **Typography** | Value | `font-family/sans|mono`, `font-size/*`, `line-height/*`, bound into text styles. |

### Styles
- **21 text styles**: Display, Heading H1–H5, Body L/M/S, Label L/M/S, Overline, Caption, Code. The font comes from your source file if it's available, otherwise Inter.
- **8 effect styles**: Elevation 0–5, plus Focus ring and Danger focus ring. Shadow colours are variables, so shadows deepen in dark mode.
- **4 grid styles**: Desktop 1440 / Laptop 1280 (12 col), Tablet 768 (8), Mobile 375 (4).

### Pages: every element on its own page
```
📘 Cover
🚀 Getting Started            atomic structure, token architecture, dark mode & density, naming, contributing, references
🎨 Foundations / Colour       primitives, source palette, semantic tables (light/dark swatches + WCAG contrast)
🎨 Foundations / Typography · Spacing · Radius & Borders · Elevation · Grid & Layout · Iconography (44 icons)
⚛️ Atoms / Button · Icon Button · Input · Textarea · Checkbox · Radio · Toggle · Badge · Tag · Avatar · Tooltip · Link · Divider · Spinner · Progress Bar
🧬 Molecules / Menu · Select · Form Field · Search Bar · Tabs · Breadcrumb · Pagination · Alert · Toast · Stat Card · Nav Item · Table · Card · Empty State
🦠 Organisms / Top Navigation · Sidebar · Page Header · KPI Overview · Filter Bar · Data Table · Modal · Settings Form Section · From Source File
📐 Templates / Dashboard · Invoices · Settings      (each in Light, Dark and Light·Compact)
📝 Changelog
```

Each component page is documented with the same sections, following the Polaris/Carbon structure:
**Summary → Usage (when / when not) → Anatomy → Variants → Light & Dark → Properties table (generated) → Do & Don't → Design tokens used (generated by scanning the layers) → Accessibility.**

### Components & variants (~45 components, ~310 variants)
- **Atoms** are bound only to tokens. Example: Button = 4 hierarchies × 3 sizes × 4 states, with Label (text), Show leading/trailing icon (boolean) and Leading/Trailing icon (instance swap) properties.
- **Molecules** are built only from atom instances. Select = Input + Dropdown Menu. Form Field = Label + Input/Select/Textarea + helper text. Table Row = Table Cells containing Avatar, Badge, Checkbox and Icon Button.
- **Organisms** are built only from molecule and atom instances. Data Table = Search Bar + Buttons + Table Header Row + Table Rows + Pagination. Modal = Form Fields + Select + Buttons. Nested instances are **exposed** so their properties can be edited from the parent.
- **Organisms from the source file**: each top-level frame of node `6349:84202` is cloned, converted to a component, and every fill, stroke and text layer is re-bound to the nearest semantic variable or text style. That gives the existing product organisms dark mode immediately. Use them as the migration reference, and replace raw layers with library instances over time.

## Developer exports
`node build.js` regenerates these from `src/tokens.js`:
- `tokens/design-tokens.json`: W3C Design Tokens format (primitive, color.light, color.dark, dimension.comfortable/compact, typography, shadow).
- `tokens/variables.css`: CSS custom properties, with `[data-theme="dark"]` and `[data-density="compact"]` overrides.
- `docs/DESIGN_SYSTEM.md`: the full written style guide (the same content as the Figma pages).

## Project layout
```
manifest.json        Figma plugin manifest (dynamic-page document access)
code.js              GENERATED plugin bundle (do not edit)
ui.html              Plugin UI
src/tokens.js        Single source of truth: primitives, semantic tokens, dimensions, type scale, elevation, grids
src/docs-content.js  Usage / anatomy / do-don't / accessibility copy for every page
src/core.js          Variables, styles, layout helpers, documentation renderer
src/foundations.js   Icons, cover, getting started, foundation pages
src/atoms.js · molecules.js · organisms.js · main.js
build.js             Bundles code.js + exports tokens & docs
test/                Strict mock of the Figma API + smoke test
```

## Development
```bash
node build.js        # bundle + exports
node test/run.js     # run the whole generator against the mock Figma API (Pro plan, Starter plan, rebuild + missing source)
```
To change a colour, spacing value or type size, edit `src/tokens.js`, rebuild, then re-run the plugin with **Rebuild** ticked.

## References
Patterns are adapted from the systems in LogRocket's *17 great Figma design systems*: IBM Carbon (data tables, density), Atlassian (semantic token naming, spacing scale), Shopify Polaris (documentation structure), Salesforce Lightning (B2B page headers), Material 3 / Fluent 2 (elevation and tonal dark surfaces), and Untitled UI / GitHub Primer (status ramps).
